# CRM возврата покупателей

Веб-приложение для фермера: помогает разобраться в клиентской базе, выделить
сегменты покупателей и подготовить кампании для повторных покупок.

## Возможности

- Обзор клиентской базы, поиск покупателей, карточки с историей заказов и согласиями.
- RFM-сегментация и рекомендации предложений для каждого сегмента.
- Конструктор кампаний: сегмент, предложение, текст, канал и время.
- Предварительный охват с объяснением исключений: нет контакта, нет согласия,
  отказ или ограничение частоты — один контакт за семь дней по всем каналам.
- Подтверждение и ручной запуск кампании, защита от повторного запуска.
- Аналитика моделируемых доставок и переходов.

**Это локальное демо.** Все данные синтетические, отправки и события только
моделируются в базе. Реальных сообщений, внешних интеграций и фонового
планировщика нет. Покупатели, заказы и согласия в интерфейсе доступны для чтения.

**Стек:** Ruby 4.0.7, Rails 8.1.4, PostgreSQL 16, Hotwire.

## Быстрый запуск

Нужны Docker Engine и Docker Compose v2. Из корня проекта:

```bash
docker compose up --build -d
docker compose logs -f web
```

Первый запуск скачивает зависимости, подготавливает схему и заполняет пустую
базу демонстрационными данными. Дождитесь запуска Rails и откройте
<http://localhost:3000/>. Проверка доступности: <http://localhost:3000/up>.

**Демодоступ:**

- Почта: `farmer@example.com`
- Пароль: `local-demo-password`

На чистой базе создаются 200 покупателей, 1 000 заказов и 400 согласий.
Данные и дата расчёта RFM фиксированы на 13 октября 2026 года.
Для немедленного запуска кампании выберите прошедшее время в UTC.

Настройки по умолчанию работают без `.env`. Для смены порта создайте `.env`
по образцу `.env.example` и задайте `PORT`. Не перезаписывайте существующий
файл. Приложение слушает только `127.0.0.1`, порт PostgreSQL на хост не публикуется.
Демо предназначено для локального просмотра, а не для размещения в интернете.

## Остановка и повторный запуск

```bash
docker compose down
docker compose up -d
```

Данные остаются в именованном томе `postgres_data` с префиксом проекта.
**Не используйте `down -v`, `db:reset` и не удаляйте том**, если данные нужны.
Сохраняйте имя Compose-проекта. После пересоздания web может потребоваться
повторный вход; данные кампаний сохраняются.
